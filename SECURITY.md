# Безопасность

Не публикуйте токены, конфигурации серверов, содержимое реальных баз, пользовательские фотографии и переписку в Issues или Pull Requests. Для воспроизведения используйте отдельные тестовые данные.

При обнаружении уязвимости используйте приватный Security Advisory во вкладке Security этого репозитория. Если приватная форма недоступна, создайте Issue только с просьбой предоставить закрытый канал связи, без подробностей эксплуатации и секретных значений.

При утечке собственного ключа немедленно отзовите его у провайдера, выпустите новый и проверьте журналы доступа. Удаление файла из последнего коммита не очищает предыдущие коммиты.

Публичная версия имеет отдельную историю. Рабочие базы, платёжные ключи и настройки действующих сервисов сюда не входят. `.env` хранится только локально; `.env.example` содержит безопасные примеры.

## Админ-панель: вход, MFA и ограничения

- Попытки входа и MFA учитываются в общем Redis-счётчике (атомарный `MULTI/EXEC` с скользящим окном), поэтому несколько воркеров видят одни и те же лимиты. В локальном демо без Redis используется ограниченный process-memory fallback; в production `RATE_LIMIT_BACKEND=redis` обязателен на старте.
- Лимиты раздельные: пара «логин + IP» и отдельный бюджет IP. Чужие неудачные попытки с другого адреса не блокируют владельца учётной записи; IP-бюджет сдерживает перебор по многим логинам.
- `X-Forwarded-For` учитывается только если непосредственный peer входит в `TRUSTED_PROXY_IPS`; берётся самый правый недоверенный адрес из цепочки. Иначе заголовок игнорируется и используется адрес сокета.
- В production старт отклоняется без `ADMIN_COOKIE_SECURE=true`, Redis-лимитера и корректных платёжных флагов. Cookie сессии: `HttpOnly`, `SameSite=Lax`, `Secure` при HTTPS, ограниченный TTL (`ADMIN_SESSION_TTL_HOURS`).
- TOTP, роли, CSRF-токен и существующие маршруты сохранены. Платёжные сценарии остаются демонстрационными: реальные YooKassa/Stars-платежи в проверках не запускаются.
